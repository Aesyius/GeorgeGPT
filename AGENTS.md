# Agent instructions

- This is a repository RAG chatbot. `vectorizer/` contains only source loading/filtering, chunking, embeddings, indexing, storage, retrieval, and integrity auditing. `Interface/` (capital I) contains chat generation/system prompt, query CLI, completion queue, and the authenticated OpenAI-compatible API for Open WebUI. `services/` contains startup/process management and model warmup; `common/` contains shared model settings, paths, and progress; `evaluation/` contains evaluation commands. Keep RAG and common modules independent of Interface/services/evaluation. The chatbot has no tools, filesystem access, Proxmox access, or command execution. Open WebUI Knowledge/RAG is not used.
- Install dependencies with `python -m pip install -r requirements.txt`.
- Ollama serves chat and embeddings. Bootup/API models and context/retention are selected in `config/models.json`; standalone query/indexing CLI model flags are unchanged. Set `OLLAMA_BASE_URL` if needed. From the project root, index with `python -m vectorizer.vectorize PATH_TO_REPOSITORY`; query with `python -m Interface.ask 'QUESTION'`. For Open WebUI set `RAG_API_KEY`, then run `python -m uvicorn Interface.server:app --host 127.0.0.1 --port 8001`; configure OpenAI-compatible URL `/v1` and model `GeorgeGPT`. Manual bootup is `pythonw -m services.bootup`, configured in `config/bootup.json`. Bootup verifies and force-restarts WebUI, API, and Ollama trees; it also recognizes the old API launch target for transition, but always launches `Interface.server:app`.
- On Windows, create the environment with `py -3.12 -m venv .venv` and use `.\.venv\Scripts\python.exe` for installation and commands; activation is optional (`.\.venv\Scripts\Activate.ps1` in PowerShell).
- Verify syntax with `python -m compileall -q vectorizer Interface services common evaluation tests`; run tests with `python -m unittest discover -s tests -p "test_*.py" -v`. `python -m vectorizer.verify_index PATH_TO_REPOSITORY` is the explicit chunking/vector/BM25 audit; do not add full metadata scans to runtime startup. The embedding integration test needs Ollama with the embedding model pulled. Live usage needs the index plus Ollama chat/embedding models.
- Chroma and the BM25 SQLite index persist under `chroma_db` at the project root, independent of working directory; explicit relative `--db-path` values are relative to current directory. Preserve existing databases, environments and runtime logs. Keep collection, DB path, and embedding model consistent for indexing/querying. Indexing excludes actual `.env` files, common key/credential files, binary/large files, caches, environments, and generated directories; review filters before indexing other repositories.
